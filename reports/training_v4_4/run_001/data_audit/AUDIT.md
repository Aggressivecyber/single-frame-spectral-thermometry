# TRAIN / DEVELOPMENT VALIDATION 数据覆盖与独立性审计

审计锚点：`623568a4f866859a9185f8ddb2ab16bc14c0d2bf`。结论是：**当前 manifest 没有显示 TRAIN 与 DEVELOPMENT VALIDATION 的精确样本/母场景重叠；signed 的独立场景覆盖很小，现有验证也已参与多轮开发，不能视为未接触的确认集。** 本审计仅运行 Python 标准库的短时 CPU 元信息检查，没有导入项目模型，没有打开 raw、标签数组或最终测试评估结果，没有生成仿真帧或训练。

证据明细保存在 [audit_metadata.json](audit_metadata.json)。本次核对的是冻结 manifest 内的哈希关系及生成代码，**未重新逐文件计算 raw/标签数组文件的哈希，也未量化近重复/相关系数**。已有会话收据中 1993 个输入、6994 个文件的复核属于之前工作；这里只引用其记录，不当作本次重新执行的检查。

TRAIN 有 1072 份不同条件标签，DEV 有 280 份；同标签的连续值、量化值及含噪输入相关。每帧 256×256 像素经过空间场构造及模糊，不可把像素数、输入行数、checkpoint 数或训练重复次数当成独立场景数。这里的“母场景数”是按生成器独立 seed 登记的层级计数，不是经过相关性估计得到的统计有效样本量 `n_eff`。

原 v4 的 2560 个非 clean 输入全部原样引用；母体、split、条件、噪声种子、raw array/file hash 与标签 hash 一致。v4.1 的保护数据是从同一拆分的旧母体产生的观测变体。两份生成代码的当前文件 SHA256 都与对应冻结 manifest 精确一致，v4.1 引用的 v4 manifest SHA256 也匹配。

**2. 几何、强度及噪声覆盖**

温度几何是 `front / multipeak / ring / stripe / flat / smooth_random`，模板几何是 `blob / multipeak / ring / stripe / filament / smooth_random`。主数据在 TRAIN 与 DEV 都覆盖 6×6=36 个温度×模板配对；各层细节见 JSON 的 `geometry_coverage`。

|母体集合|TRAIN 非空几何配对/36|DEV 非空几何配对/36|
|---|---:|---:|
|主数据|36|36|
|主保护子集|36|24|
|signed|12|6|

signed TRAIN 每种温度几何仅有两个模板配对：第一个循环是 `(front,blob)、(multipeak,multipeak)、(ring,ring)、(stripe,stripe)、(flat,filament)、(smooth_random,smooth_random)`；第二个循环将模板类别向后错一位。DEV 仅包含第一个循环，每配对一母体。**六类温度和六类模板各自都出现，不等于 36 个交叉组合都有证据。** DEV 保护的 96 个门槛为主组 6×4×2 加 signed 6×4×2；其中 signed 每个门槛只有一母体/一输入。当前分组按温度几何、条件、输入类型，不以模板几何为键。

主模板的 preblur 峰值为 blank=0、weak∈[25,55]、normal∈[140,280]、strong∈[320,520] e；signed 峰值固定为 ±45、±180 e，没有 signed strong、近零非零系数或单幅图内正负并存的模板覆盖。signed 使用额外 +250 K 的温度平移，因此它不是在全部主数据分布上随机翻转符号。当前 18 个 signed 母体的连续谱与模板合法性缩放均为 1；合法性记录给出的最小 band=135.659 e、最小 expected=2058.902 e、最大 expected=35055.156 e。上述数值是既有生成回执，未由本次数组复算。

噪声全部采用同一物理配置的 Poisson shot noise + 3 e Gaussian read noise，再经固定 12 bit ADC；连续值和仅量化观测是确定性保护输入，不是额外独立噪声抽样。主数据每母体/条件有两种 seed，signed 只有一种。模板谱响应、滤波/QE、PSF、载频、曝光及读噪声不在本数据中做跨配置变化，且配置明确为 synthetic engineering fixture，不能外推为实测谱响应或相机鲁棒性。

signed 的 72 个含噪行没有显式写入 `noise_seed` / `noise_index`，只能按已匹配哈希的生成代码还原种子。还原结果保存在 [signed_noise_seed_derivation.json](signed_noise_seed_derivation.json)：所有含噪输入共 2632 个种子，TRAIN 2096、DEV 536，拆分间无交集。另一个溯源细节是 signed 母体的 `temperature_field_sha256` 来自 +250 K 前的 `mother_state`，应注明它不是变换后温度标签哈希；新数据应同时保存变换后场哈希。

**3. “12 个母体、24 个负含噪输入”真正提供的证据**

一个 signed 母体的 continuum、幅度、背景与模板空间形状固定，negative_weak 和 negative_normal 只改变模板幅度；各自一个噪声实现。因而 24 个负含噪输入对应 **12 个空间场实例、24 个母体×强度观测、每个条件仅一个噪声实现**。匹配正负与不同强度有利于配对机制比较，但不是增加了新母场景。

|500 次更新中的抽样|原序列前缀|negative_balanced|
|---|---:|---:|
|全部微批次|2000|2000|
|实际不同输入|1183|851|
|实际不同母体|264|232|
|signed 微批次|100|575|
|负含噪微批次|26|513|
|不同负含噪输入|15|24|
|不同负含噪母体|11|12|

negative_balanced 的第二个含噪位置有 500 次：24 个固定输入分别出现 20 或 21 次（4 个出现 20 次、20 个出现 21 次）。其他三个位置的 1500 项与控制逐例相同；另有 13 次负含噪来自保留的第一位置。因此“513 次负含噪学习”不能改写成 513 次独立母场景验证。它同时减少了总体输入/母体暴露面，不能仅用负组局部改善证明数据覆盖问题已解决。

原 1500 更新序列也只是有放回抽样：6000 微批次实际用到 2043 个不同输入、268 个母体、300 个 signed 微批次。重复训练和多个 checkpoint 是同一固定池上的优化轨迹。

**4. 跨拆分风险的证据边界**

本次 TRAIN/DEV 直接交集检查中，下列项目全部为 0：`case_id`、`mother_id`、raw 路径、raw 数组 hash、raw 文件 hash、标签路径、标签文件 hash、母 seed、温度/幅度/模板/背景 seed，以及温度场、幅度场、模板形状 hash。保护子集的母体确实来自所属拆分；实际抽样序列全部只用 TRAIN。

因此，**没有证据把共享几何类别或同一物理生成器自动认定为跨拆分精确泄漏**。现有实质限制是：同源生成器/固定传感器配置的分布相关性、signed 配对覆盖窄、可能的近重复尚未测量，以及验证集的适应性使用。母体 hash 无碰撞只能排除记录层面的精确重复，不能证明统计独立或真实采集泛化。

开发适应性有直接源码证据：v4 用 4 个验证母体的 32 个含噪输入选物理骨干/正则；v4 和 v4.1 用完整验证作模型/控制选择；v4.1 的传统解码器也在主含噪验证上选 lambda。v4.3 的 tau/power 数值只用 TRAIN 残差与输入类型定标，但方法设计已受开发验证启发，源码也保存了 `validation_motivated_diagnostic=true`。这不是“验证标签进入训练张量”的证据，却意味着当前 776 帧只能称 DEVELOPMENT VALIDATION。

这里只查看旧 manifest 中登记的 64 个 final 母体/seed 元信息，其 ID 和场 seed 与使用中的拆分无交集。没有打开 final 帧、标签、评估结果；也没有扫描或证明工作区不存在任何未登记的 final 输出。已有报告的 `final_test_used=false` 是原收据声明。本审计自身的最终测试数组/结果访问为 0。

**5. 固定 continuum 后若 signed 仍失真：已冻结的最小覆盖修复设计**

设计保存于 [frozen_data_repair_plan.json](frozen_data_repair_plan.json)，母场景与噪声种子登记于 [repair_parent_registry.json](repair_parent_registry.json)。状态为 `FROZEN_DATA_DESIGN_ONLY_NOT_LAUNCHED`。没有运行仿真生成器，也没有创建 raw、标签、缓存或启动训练。激活条件是固定 continuum 对照按冻结预算完成并核验后仍存在 signed 失真，再单独登记有界生成/训练任务。

具体方案只补最明显的覆盖缺口：保留现有 12 个 TRAIN signed 母体，新增其余 24 个缺失的温度×模板配对，使 TRAIN 每格一母体；另新增 36 个全配对的锁定开发确认母体。现有 6 个 signed DEV 母体已反复查看，不能把它们改名为新确认数据，因此新确认集必须从新 seed 开始。每母体保持匹配的 ±45/±180 e、连续值/量化值与两个噪声实现。旧 12 母体各条件只补第二个噪声，共 48 个额外输入，标签原件不动。

|新增内容|母体|新输入行|
|---|---:|---:|
|TRAIN 缺失几何配对|24|384|
|旧 TRAIN 母体第二个噪声|0|48|
|锁定开发确认全配对|36|576|
|合计|60|1008|

实施后 TRAIN 将为 3008 输入、292 母体，其中 signed 为 36 母体、576 输入；旧 776 开发帧原样保留并单列。新增 240 个条件标签，48 个补噪输入复用旧标签。该规模是“一格一母体”的覆盖下限，不能保证统计功效；任何一个几何格内都不足以估计母体间方差。

新母 seed 使用 `600000 + 1009×pair_index`（TRAIN 缺失格）与 `700000 + 1009×pair_index`（锁定 DEV），温度/幅度/模板/背景分别 +1/+29/+53/+71；具体 60 个描述符和所有噪声 seed 已登记。828 个计划 seed 值无内部碰撞，也不与旧 TRAIN、旧 DEV 和原最终测试注册的字段/噪声 seed 重叠。split 在场构造前固定，同母体全部符号、强度、输入类型和噪声归属同一 split。

继续使用已冻结的母场构造、+250 K、峰值、合法性缩放、物理配置和噪声模型，避免同时改动强度范围或传感器条件。所有非法/饱和/非有限案例保留并停止；不按性能重抽种子。新行显式记录噪声 seed/index、变换后场 hash、实际缩放、raw/标签/cache 身份。原最终测试登记保持原样。

训练方案必须另行冻结。若要作数据因素对照，应固定初始化、continuum 处理、优化器、更新预算、损失和门槛，保持每条件/输入类型的暴露数及 unsigned 输入逐项配对，只改变 signed 母体/噪声选取。原 5% signed 抽样未必实际覆盖扩充池，必须报告“实际抽到的格/母体”；只把样本写进 manifest 不等于完成覆盖修复。

新锁定 DEV 不参与残差定标、选 sampler、选 tau/power、挑 checkpoint、阈值或提前停止；模型及固定末点确定后才做一次评估。若结果又被用来改模型，这批就转为开发数据，不再声称独立确认。报告按母体做配对聚合，区分符号、强度、两种噪声及几何，确认单位为 36 母体，而不是 576 行或像素。它仍是同生成器的模拟确认，独立实测与传感器漂移不在本最小方案内。

- 数据身份：母体/条件/噪声/几何 split 清单、每行 raw array/file SHA256 和标签 SHA256、实际生成器/物理配置/缓存 key；记录所有异常、缺失与合法性缩放，不删除失败样本。冻结清单 hash 与实际文件复核结果分开。

- 固定 continuum 对照：固定输出字段的逐帧不变性检查、可训练参数名单、optimizer 只更新目标参数、冻结物理缓存与缓冲区哈希；训练前后及原生重载证明。仅输出数值接近不等同于实现路径冻结。
- 运行与模型：实际解释器/依赖/设备、随机种子、已完成 optimizer 与 Adam 步数、初始化/末点参数和 checkpoint SHA256、失败/中断日志、原生推理重载与复现；所有路径在 E/D。
